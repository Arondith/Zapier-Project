Turn a crisis request into a coordinated response workflow.

ReliefRelay is a portfolio prototype for NGOs, local governments, and volunteer response teams. It structures requests for food, water, shelter, medical support, rescue, and infrastructure assistance, then routes them through Zapier for logging, notification, acknowledgement, and human review.

The problem

During disasters, information can be as scarce as supplies.

Requests often arrive through calls, messages, forms, and social media. ReliefRelay shows how a lightweight web interface and automation layer can standardize that information, reduce repetitive encoding, and move each request toward the right human response team faster.

Automation architecture

One request, one traceable workflow

The frontend collects only operationally useful fields. JavaScript validates and assigns a transparent routing tier. Zapier can then distribute the same structured record across the tools a response organization already uses.

01

Capture

Collect need type, safe contact method, area, people affected, urgency, and essential context.

02

Route transparently

Rule-based routing uses explicit conditions and records why a request was marked urgent.

03

Sync through Zapier

Send a structured payload to Sheets, Airtable, a CRM, email, Slack, or another connected system.

04

Human response

Responders review, verify, assign, contact, and close the request. Automation never replaces judgment.

Resilience

Offline-aware queue

If the browser loses connectivity while live mode is enabled, the request can wait locally and retry when the connection returns.

Interoperability

Works with existing tools

Zapier can forward the same request to Sheets, Airtable, email, Slack, CRM platforms, or other systems without rebuilding the frontend.

Accountability

Explainable routing

Each routing tier includes a recorded reason. The system avoids opaque automated decisions and keeps human review explicit.

Privacy

Data minimization

The prototype asks for operationally useful information and warns against entering real personal data in a public demonstration.

Responsible automation

What the system should never decide alone

No automated denial. A low routing tier must never mean a person is refused assistance.

No AI-only emergency triage. AI may summarize text, but trained humans verify urgency and action.

No secret scoring. Routing rules are visible in the code and should be reviewed by the deploying organization.

No public production secrets. Webhook URLs and credentials belong behind a secure backend in a real deployment.

Configuration

Automation settings

This prototype saves the URL only in this browser. A real deployment should send requests through a secured backend so the webhook is never exposed to clients.
